# Scoop Release Automation Helper (ProcessSentinel Pattern)

This directory provides a turnkey template and prompt system to connect any personal application project to **Zunaid-Scoop-Bucket**.

Whenever you release a new version in your project repository, running its release pipeline will:
1. Package the binaries into a release zip.
2. Compute the exact SHA-256 hash.
3. Update the canonical Scoop manifest (`<app>.json`) inside the project repository.
4. Commit and push the manifest to `main`.
5. Publish the GitHub Release with `gh release create`.
6. Automatically dispatch a workflow run in `Zunaid-Scoop-Bucket` to pull the latest manifest and update the bucket.

---

## Why the ProcessSentinel Pattern?

In this bucket, we distinguish between:
- **Third-party apps** (e.g. `rapidraw`, `scratch-md`, `calcpad-ce`): Handled via Scoop's periodic **Excavator** (`excavator.yml`), which crawls upstream GitHub releases.
- **Your own authored projects** (e.g. `ProcessSentinel`, `VisioFlow`): Handled via **In-Repo Canonical Manifest + Direct Sync Workflow**.

### Advantages for your own projects:
- **Single Source of Truth**: The manifest (`<app>.json`) lives in the project repo alongside its source code. If shortcuts, launch arguments, persist directories, or environment variables change, you modify the manifest in the same commit or PR as the application code.
- **Guaranteed Hash Correctness**: The hash is computed locally from the actual artifact just built, completely avoiding regex/naming mismatches in Excavator.
- **Instantaneous Updates**: No waiting for monthly cron jobs or manually running Excavator. The release script triggers the bucket sync immediately upon release.
- **One-Command Release**: `.\scripts\release.ps1 -Version "X.Y.Z" -Force` completes the entire end-to-end publishing and bucket update pipeline.

## Quick Setup Workflow for a New Project

### Step 1: In the Project Repository
1. Copy the contents of [`PROMPT_FOR_AI.md`](PROMPT_FOR_AI.md) and paste it into your AI assistant in that project.
2. The AI will:
   - Identify your project's build output folder (e.g., `dist/MyApp` or `target/release`).
   - Create `<app>.json` at the root of the project.
   - Create `scripts/release.ps1` tailored to that project.
   - Add release safety rules to the project's `AGENTS.md`.
   - Provide the two small files needed for `Zunaid-Scoop-Bucket`.

### Step 2: In Zunaid-Scoop-Bucket (One-Time Setup per Project)
Add the two files generated by the AI:
1. `.github/workflows/sync-<app>.yml` (from [`bucket-sync-workflow.yml.template`](templates/bucket-sync-workflow.yml.template))
2. `bin/sync-<app>.ps1` (from [`bucket-sync-script.ps1.template`](templates/bucket-sync-script.ps1.template))
3. Copy the initial `<app>.json` to `bucket/<app>.json` and commit.

## How It Works in Action

```
[Project Repo]
User / AI runs: .\scripts\release.ps1 -Version "1.2.0" -Force
  │
  ├─► Builds & packages dist\MyApp into MyApp-v1.2.0-windows-x64.zip
  ├─► Calculates SHA-256
  ├─► Updates <app>.json with version and SHA-256
  ├─► Commits & pushes <app>.json to main
  ├─► Publishes GitHub release: gh release create v1.2.0 ...
  └─► Triggers Scoop bucket sync:
        gh workflow run sync-<app>.yml -R zunaidFarouque/Zunaid-Scoop-Bucket
              │
              ▼
[Zunaid-Scoop-Bucket]
GitHub Action: .github/workflows/sync-<app>.yml triggers
  │
  ├─► Runs bin/sync-<app>.ps1
  ├─► Downloads raw <app>.json from project repo main branch
  ├─► Formats JSON (formatjson.ps1)
  └─► Commits & pushes update to bucket/<app>.json
```
